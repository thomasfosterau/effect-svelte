`Navigation.goto`, `Navigation.invalidate`, `Navigation.invalidateAll`, `Navigation.refreshAll`, `Navigation.preloadData`, `Navigation.preloadCode` and `Forms.applyAction` (in `./client`) now fail on the Effect error channel when SvelteKit rejects or throws, instead of dying with a defect. The `Navigation` wrappers fail with the new `Navigation.NavigationError` (`operation` names the wrapper, `cause` is SvelteKit's original reason) and `Forms.applyAction` with the new `Forms.ApplyActionError` (`cause`). SvelteKit 3 rejects, for example, `goto` to a URL outside the app (external, or matching no route), `preloadData` for an `href` outside the app, and a navigation whose `beforeNavigate` / `onNavigate` callback throws, and each of these functions throws when called during server rendering. Their types change from `Effect<void>` to `Effect<void, NavigationError>` / `Effect<void, ApplyActionError>` (`preloadData` keeps its success type). Code that recovered from these failures with `Effect.catchCause` / `Effect.catchDefect` should now handle them as failures, for example with `Effect.catchTag("NavigationError", ...)`. An `onResult` that returns `Forms.applyAction(result)` still type-checks, since `Forms.enhance`'s handlers may now fail (see its new `onError` option).
