`Forms.enhance` (in `./client`) now accepts `onSubmit` / `onResult` handlers that fail, and a new `onError` handler beside them: `Forms.enhance({ onSubmit, onResult, onError }, { runtime })`. `onError` receives the error a handler failed with, typed as the union of the handlers' error types, and runs on the same runtime as the handlers (it must not fail itself). Write it after the other handlers: written before one whose parameters are not annotated (such as `onResult: ({ result }) => ...`), it still type-checks, but its `error` parameter is `unknown`; an annotated `onError` must accept every error the handlers fail with, in either order. A failed `onSubmit` also cancels the submission, and a failed `onResult` does not fall back to SvelteKit's default behaviour. Without `onError`, a failure rejects the promise SvelteKit awaits with the error itself, as a defect does (and as `Effect.orDie` did), and defects and interruptions still take that path even when `onError` is given. So `onResult: ({ result }) => Forms.applyAction(result)` type-checks, its `ApplyActionError` going to `onError` when one is given. `EnhanceHandlers` gains `ESubmit` / `EResult` type parameters (defaulting to `never`, so handlers that cannot fail behave as before) and an `E` parameter for `onError`'s error (defaulting to their union).
