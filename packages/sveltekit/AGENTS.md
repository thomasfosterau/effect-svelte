# packages/sveltekit — `@thomasfosterau/effect-sveltekit`

SvelteKit integration for Effect v4: load / action / endpoint wrappers, remote functions, a universal runtime, the `effectKit()` Vite plugin and an Effect deployment adapter. Read the root [AGENTS.md](../../AGENTS.md) first.

The fallow zones in `.fallowrc.json` enforce the "may import" column between this package's files (a new file outside the listed server / client / adapter / build zones is universal); `no-restricted-imports` overrides in the root `vite.config.ts` enforce the external specifiers. A new entry adds a row here, an entry in `pack.entry` (`vite.config.ts`), `exports` (`package.json`), `.fallowrc.json` (`entry` and a zone) and the package `README.md`.

## Invariants

- **No source file matches SvelteKit's remote-module matcher** (`/[/.]remote(\.[^/]+)+$/`, e.g. `remote.server.ts`, `*.remote.ts`): kit's build rejects a built file whose exports are not all remote functions. That is why the factories live in `src/remote-functions.ts`; `tests/remote-module-naming.test.ts` guards it.
- **`$app/*` and `node:` stay external** (`pack.deps.neverBundle`); the consuming app provides `$app/*`.
- **This package is a runtime boundary.** SvelteKit calls loads, actions, endpoints, hooks and remote functions as Promise APIs, so the wrappers run the caller's Effect there: on the caller's runtime where there is one, and through `src/internal/run.ts` (`runPromise`, `runPromiseExit`, `runSync`) where there is none. That module is the only file that calls `Effect.runPromise` / `runSync` / `runFork`; the `effect/effect-run-in-body` lint rule is on everywhere else, tests included (they use `@effect/vitest`'s `it.effect` / `it.live`). A failure the caller did not map surfaces as a 500 / `error()`, never as an unhandled rejection. The adapter's `adapt` build hook (`src/adapter/index.ts`) is a boundary too, and `src/adapter/**` may import nothing else from this package: it runs `writeBuild` (`src/adapter/build.ts`, an Effect program over `FileSystem`) on a `ManagedRuntime` over `NodeFileSystem.layer` that it creates per build and disposes when the build ends. Dispose a `ManagedRuntime` only after its run has settled (`runtime.runPromise(program).finally(() => runtime.dispose())`), never from inside the program it is running (`Effect.ensuring(runtime.disposeEffect)`): that passes on the pinned `effect` but never settles on `effect` 4.0.0, the published peer floor.
- **No type assertions outside `src/internal/unchecked.ts`.** That module holds the narrowings neither the compiler nor a runtime check can verify, each as one function documented with its invariant (the root `vite.config.ts` turns the two assertion rules off for that file only). Before adding one, fix the type: where a layer, runtime or input may be left out, the public signature is a set of overloads and the implementation takes the union of their argument tuples and tells them apart with a type predicate (`Endpoint.fromHttpEffect`, `runServerLoad`); where `Effect.provide` leaves an `Exclude` TypeScript cannot resolve for a generic `R`, use `src/internal/provide.ts`. A type argument given to an Effect API's own parameter in place of a conditional it cannot resolve (`ReqR` of the `toWebHandler` family) is kept in one documented function (`routerWebHandler` and `layeredWebHandler` in `src/server/Endpoint.ts`, `toWebHandler` in `src/adapter/handler.ts`).
- **`@thomasfosterau/effect-svelte` is a dependency but is not imported.** It is kept deliberately (#186) so a compatible version installs alongside; the README tells consumers to list it themselves to import it, and fallow's `ignoreDependencies` records why.

## Tests

`tests/` runs in Node against the rune-free cores in `src/internal/`; `tests/client/` runs under happy-dom with the Svelte plugin and `$app/state` / `$app/navigation` / `$app/forms` aliased to the stand-ins in `tests/client/fixtures/`.
